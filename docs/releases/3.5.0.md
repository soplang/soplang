# Soplang 3.5.0 implementation milestone

Status: implemented in the development source. Distribution and publication
have not been scheduled.

## Project and test commands

- `soplang fmt`, `check`, `test`, and `doc` format, analyze, test, and document
  source. Formatting preserves comments and checks the result before atomic
  replacement.
- Project `run` and `dhis` commands accept strict and offline options; `add`,
  `remove`, and `update` manage manifest dependencies.
- Top-level `tijaabo` blocks support assertions, expected runtime errors,
  setup and cleanup, filtering, isolated parallel workers, and source coverage.

## Editor and debugging

- The language server provides diagnostics, completion, hover, signature help,
  semantic tokens, definitions, references, rename, formatting, and code
  actions. It tracks UTF-16 document edits and imported source identities.
- The VS Code extension starts the native language server and includes Soplang
  and `schema.sop` syntax, snippets, and diagnostics.
- Source debugging supports breakpoints, stepping, caller frames, and bounded
  local inspection in the JIT and instrumented LLVM executables. `profile`
  reports function calls and execution time.

See [CLI diagnostics](../language/cli.md),
[database editing](../language/data.md#schema-diagnostics-and-editing), and
the [roadmap](../../ROADMAP.md) for commands and limits.

The source debugger is a command-line debugger with LLVM instrumentation; it
does not emit DWARF or provide a Debug Adapter Protocol server. Cross-platform
package verification is still required before a published release.
