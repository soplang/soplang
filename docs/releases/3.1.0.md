# Soplang 3.1.0 implementation milestone

Status: implemented locally. Distribution builds and publication are pending.
The published release remains 3.0.1.

## Runtime foundations

- Independent execution contexts own globals, classes, functions, and errors.
- Opaque, reusable handles reject expired and foreign values.
- Tracing collection reclaims temporary values and collection cycles. Generated
  stack roots, captured environments, native snapshots, and Rust pins retain
  live values through collection.
- Execution boundaries return recoverable errors to embedding callers and let
  REPL sessions continue after failed snippets.
- JIT backends own the literal and diagnostic bytes embedded in generated code.
  Callers can drop compiler input; backend teardown releases code and its data.

The [ownership design](../architecture/RUNTIME_CONTEXTS.md) compares memory
strategies and defines the resource lifecycle required by future file and
network APIs. Those APIs are not part of this milestone.

## Errors and cleanup

```soplang
hawl tijaabada() {
    tijaabi {
        tuur khalad("Tijaabo ayaa fashilantay.", "T001")
    } dhammee {
        qor("Hawshii waa la dhammeeyey.")
    }
}
tijaabi {
    tijaabada()
} qabo (fariin, xog) {
    qor(fariin, xog.summad)
}
```

`tuur` raises text or immutable structured errors. `dhammee` runs on normal
completion, errors, returns, breaks, and continues. Errors preserve causes,
compiled function traces, filenames, lines, columns, and source carets.
Existing single-binding catches continue to receive message text.

## Strings and calls

```soplang
door magac = "Ayaan"
qor(f"Salaan, {magac}! Wadarta: {2 + 3:03d}")
qor("{magac}: {da:03d}".qaabee({magac: magac, da: 7}))
qor(e"Sadar koowaad\nSadar labaad")
qor(r"C:\temp\new")
```

Escaped, raw, multiline, and interpolated strings preserve original source
positions. `qaabee` provides value and template formatting. Expressions evaluate
once in order; failures stop subsequent fields or arguments.

Compiled functions, closures, methods, and constructors use argument vectors
without the former eight-value limit. Returned, indexed, grouped, and stored
callables can be invoked directly. Arity and type validation still apply.

## Numeric consistency

Integer arithmetic wraps consistently in both backends and build profiles.
Remainder handles the minimum integer, large floats, and signed zero. Numeric
ranges compare integer bounds exactly and stop before overflow. Floating-point
steps that cannot advance toward a remaining endpoint raise recoverable errors.

## Verification and limits

See [3.1 verification](../testing/RUNTIME_3_1.md) for commands and evidence.
All new execution fixtures run through Cranelift and LLVM. Diagnostic examples
verify original lines, Unicode columns, and caret spans in both paths.

These changes do not implement the 3.2 collections and argument features,
3.3 I/O, 3.4 projects/packages/web/ORM, 3.5 tooling, or 3.6 concurrency work.
Contexts remain confined to one thread. Managed heap statistics exclude
retained compiler metadata and JIT code. Native stack exhaustion, process
termination, and allocator exhaustion are not recoverable language errors.

The [Somali wording supplement](../language/runtime-error-wording.md) records
new public names and diagnostics for terminology review. Documentation remains
in English; user-facing language diagnostics remain in Somali.
