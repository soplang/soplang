# Soplang 3.4.0 implementation milestone

Status: implemented in the development source. Distribution and publication
have not been scheduled.

## Modules and packages

- Namespace and selective imports, explicit exports, import aliases, cached
  module initialization, and cycle diagnostics.
- `soplang init` creates an application or library with `soplang.toml`.
  Dependencies may come from Git repositories or local paths. One root lock
  pins Git commits and content hashes, and a verified cache supports offline
  builds.

See [modules](../language/modules.md) and [packages](../language/packages.md).

## Web applications and data

- The bundled `web` module provides routes, groups, middleware, JSON and HTML
  responses, forms and multipart uploads, templates, static files, cookies,
  sessions, authentication hooks, CORS, request logs, TLS, and an in-memory
  application test client. Request handling remains sequential.
- `schema.sop` defines scalar database models. The bundled data API and
  generated typed clients support validation, safe query filters, pools,
  transactions, and additive migrations. SQLite, PostgreSQL, CockroachDB,
  MySQL, MariaDB, MongoDB, and SQL Server use real connectors.
- PostgreSQL, CockroachDB, MySQL, and MariaDB can require verified TLS and
  extend system trust with a PEM CA. MongoDB and SQL Server use their driver
  connection settings for TLS.

See [web](../language/web.md) and [data](../language/data.md) for exact APIs,
connector behavior, migration limits, and deployment considerations.

The data client supports typed equality filters and scalar fields. It does not
implement joins, relations, arbitrary SQL, destructive migrations, or schema
drift repair. Concurrent serving remains part of 3.6.
