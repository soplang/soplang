# Soplang 3.0.1

Soplang 3.0.1 fixes English text in the command-line interface and diagnostics.
Existing programs, flags, keywords, compatibility spellings, and compiler
backends retain their behavior.

## Somali help and diagnostics

- CLI help includes Somali descriptions, headings, placeholders, and defaults.
  Invalid options and values receive Somali explanations with the existing
  exit statuses.
- File access, console input/output, REPL startup, Cranelift, LLVM, and runtime
  discovery failures receive contextual Somali messages. Infrastructure errors
  no longer report nonexistent source line and column zero.
- Source diagnostics retain their file, line, column, error code, and caret.
  Caught runtime errors have the same Somali message in JIT and LLVM programs.
- Set `SOPLANG_ERROR_DETAILS=1` to include original external tool/OS details
  under `Faahfaahin farsamo:` on stderr. Those troubleshooting details can be
  English; normal explanations are Somali.

## Documentation and verification

The release includes the Python/Soplang 2/Soplang 3 benchmark report and
updated compiler, package, Docker, and roadmap documentation committed since
3.0.0. The benchmark results describe their recorded 3.0.0 compiler revision;
they are not new measurements of this patch.

The package checks cover localized help, argument errors, runtime discovery,
toolchain compatibility, JIT execution, and LLVM executables. Release packages
must pass the native and container gates before publication.

## Installation

Use the assets and `SHA256SUMS` attached to this release. Keep the compiler
and its matching `lib/soplang` runtime together. Native `--build` requires
clang, the platform linker/SDK, and the exact Rust toolchain recorded in
`lib/soplang/rustc-version.txt`. JIT execution and the REPL need neither Rust
nor clang. The published platforms and package requirements are determined by
the verified release assets.
